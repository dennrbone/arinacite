# Отчёт: CMS интернет-магазина билетов «Ритм города»

## 1. Что разработано

Исходный сайт музыкального фестиваля переведён на PHP и MySQL. Его оформление и анкета участника сохранены. Добавлен небольшой интернет-магазин билетов и панель управления содержимым сайта.

Покупатель может:

1. Открыть главную страницу и увидеть актуальные билеты из базы данных.
2. Добавить билеты в корзину и изменить количество.
3. Создать аккаунт по имени, email и паролю, войти и сменить пароль в личном кабинете.
4. Оформить заказ как гость или после входа; заказ вошедшего покупателя появляется в его личном кабинете.
5. Отдельно заполнить анкету участника фестиваля.

Администратор может:

1. Войти в защищённую панель.
2. Добавить или изменить билет, цену, описание и остаток.
3. Скрыть билет с сайта или снова показать его.
4. Просмотреть заказы и анкеты.
5. Подтвердить или отменить заказ. При отмене остаток билетов восстанавливается.
6. Изменить заголовок и описание главной страницы.

Оплата через сайт и отправка писем не реализованы. Кнопка «Подтвердить заказ» сохраняет заказ в MySQL, но не списывает деньги. Анкета участника также сохраняется в MySQL, однако сама по себе не является заказом билета.

## 2. Структура проекта

    .osp/project.ini          настройка домена и публичного каталога OpenServer
    app/bootstrap.php          подключение к БД, сессии, корзина, защита форм
    app/config.example.php     образец настроек MySQL
    app/config.php             рабочие настройки MySQL; на Linux уже настроены локально, в архив не входят
    app/header.php             шапка сайта
    app/footer.php             подвал сайта
    bin/create_admin.php       создание учётной записи администратора
    bin/start_local.sh        локальный запуск PHP с рабочими сессиями
    database/schema.sql        создание базы, таблиц и трёх примеров билетов
    database/upgrade_accounts.sql  одноразовое обновление старой базы для аккаунтов
    public/index.php           главная страница, каталог и анкета
    public/account.php         регистрация, вход, кабинет и смена пароля
    public/cart.php            корзина
    public/checkout.php        оформление заказа
    public/order-success.php   подтверждение оформления
    public/register.php        сохранение анкеты участника
    public/admin/index.php     панель управления
    public/style.css           стили
    public/script.js           ползунок оценки и плавное появление блоков
    archive/                   предыдущая статическая версия сайта (только в рабочей папке)

Публичный каталог — только public. Файлы app, database и bin находятся за пределами открываемой браузером папки.

## 3. Требования

- Windows с Open Server Panel 6.
- Рабочие модули HTTP-сервера, PHP 8.2 или новее и MySQL 8.
- В выбранной версии PHP включён драйвер pdo_mysql. Для запуска сайта также нужны стандартные расширения PDO и session. Если переносите базу с уже созданными администраторами или покупателями и Argon2id-хешами, версия PHP на Windows должна поддерживать Argon2id.
- Любой современный браузер.

Open Server Panel 6 рассчитан на Windows; на текущем ПК с Linux сайт запускается через установленные PHP 8.5.4 и MySQL 8.4.11. Доступны PDO, pdo_mysql, mysqli, mysqlnd и session. Все PHP-файлы проверены командой php -l, а JavaScript — командой node --check. Сквозной сценарий проверен на установленном MySQL 8.4.11. После переноса на Windows нужно отдельно проверить запуск модулей OpenServer.

## 4. Запуск на текущем ПК (Linux)

Рабочая база `ritm_goroda` и закрытый файл `app/config.php` уже настроены. Пароль базы находится только в этом локальном файле; его нет в архиве для передачи. Учётная запись администратора ещё не создана — выберите имя и пароль самостоятельно. Покупатель создаёт аккаунт сам через форму на сайте.

Откройте терминал и выполните:

    cd /home/dennrbone/arina
    mysql -e "SELECT VERSION();"
    mysql-start  # только если MySQL ещё не запущен
    php -v
    php bin/create_admin.php
    ./bin/start_local.sh

После запуска последней команды откройте `http://127.0.0.1:8000/`, регистрацию покупателя — `http://127.0.0.1:8000/account.php?view=register`, а панель — `http://127.0.0.1:8000/admin/index.php`. Пока сайт используется, оставьте терминал со скриптом `start_local.sh` открытым. Для остановки нажмите `Ctrl+C`. При следующем запуске базу заново импортировать и администратора заново создавать не нужно: достаточно проверить MySQL, при необходимости выполнить `mysql-start`, затем `./bin/start_local.sh`. Если порт 8000 занят, выполните `./bin/start_local.sh 8001` и измените адрес в браузере. Скрипт задаёт доступный каталог PHP-сессий в `.runtime/sessions`; без него формы на этой установке могут отвечать «Неверный защитный токен». Команда `mysql-stop` останавливает MySQL после работы, но может повлиять на другие локальные сайты, использующие этот сервер.

Если вы хотите перенести на Windows уже накопленные заказы и учётные записи, отдельно экспортируйте базу в SQL-файл. Подробный порядок приведён в `Инструкция_запуск_и_перенос_Windows.docx`.

## 5. Установка в Open Server Panel 6

### Шаг 1. Скопировать проект

Скопируйте всю папку проекта в:

    C:\OSPanel\home\ritm-goroda.local\

После копирования должны существовать пути:

    C:\OSPanel\home\ritm-goroda.local\.osp\project.ini
    C:\OSPanel\home\ritm-goroda.local\public\index.php
    C:\OSPanel\home\ritm-goroda.local\database\schema.sql

Имя папки соответствует секции [ritm-goroda.local] в .osp/project.ini. Настройка web_root указывает на папку public. Если OpenServer установлен на другом диске, замените только начальную часть пути.

### Шаг 2. Включить модули

Перезапустите Open Server Panel, чтобы он обнаружил новый проект. В меню проекта выберите установленный HTTP-сервер (например, Apache) и PHP 8.2 или новее. Включите модули проекта и модуль MySQL. Если выбрана MySQL-8.0 вместо MySQL-8.4, это понадобится учесть в настройке подключения ниже.

Важно: имя хоста MySQL для Open Server Panel 6 — имя включённого модуля, например MySQL-8.4. Использовать localhost для подключения к MySQL в этой конфигурации не следует.

### Шаг 3. Создать базу и таблицы

Откройте «Интерфейс командной строки» OpenServer и выполните:

    osp project ritm-goroda.local
    osp add MySQL-8.4
    mysql -h MySQL-8.4 -P 3306 -u root < database\schema.sql

Если для root задан пароль, добавьте к команде mysql ключ -p. Если у вас модуль MySQL-8.0, замените MySQL-8.4 в обеих командах на MySQL-8.0.

В качестве альтернативы откройте файл database/schema.sql в клиенте MySQL, например DBeaver, и выполните его целиком. Для новой установки скрипт создаст базу ritm_goroda, таблицу users, связь orders.user_id и три примера билетов.

Если база была создана предыдущей версией этого проекта, **вместо повторного импорта schema.sql** один раз выполните `mysql -h MySQL-8.4 -P 3306 -u root < database\upgrade_accounts.sql`. Скрипт добавляет аккаунты и связь с заказами, сохраняя существующие записи. Повторно этот скрипт не запускают. Для root с паролем добавьте `-p`.

### Шаг 4. Настроить подключение

В корневой папке проекта выполните:

    copy app\config.example.php app\config.php

Откройте app/config.php и проверьте параметры:

- db_host — фактическое имя включённого модуля MySQL, например MySQL-8.4.
- db_port — обычно 3306.
- db_name — ritm_goroda.
- db_user — пользователь MySQL, в примере root.
- db_password — пароль выбранного пользователя, если он есть.

Файл app/config.php хранит настройки подключения. Он не находится в папке public и указан в .gitignore. Не публикуйте его вместе с паролем.

### Шаг 5. Создать администратора

В той же консоли, находясь в корне проекта, выполните:

    php bin\create_admin.php

Введите имя администратора латинскими буквами, цифрами, знаком подчёркивания или дефисом (от 3 до 60 символов) и пароль не короче 10 символов. Пароль в базе хранится в виде хеша. При повторном запуске с тем же именем скрипт сообщит, что пользователь уже существует.

### Шаг 6. Открыть сайт

Откройте в браузере:

    https://ritm-goroda.local/

Если локальный сертификат OpenServer не доверен браузеру, используйте настройки сертификатов OpenServer либо для локального просмотра откройте http://ritm-goroda.local/. Для Firefox официальный справочник OpenServer отдельно описывает импорт корневого сертификата.

Регистрация покупателя и вход:

    https://ritm-goroda.local/account.php?view=register
    https://ritm-goroda.local/account.php?view=login

Панель управления:

    https://ritm-goroda.local/admin/index.php

Файлы PHP нельзя открывать через file:///...: в этом режиме сервер PHP и MySQL не работают. Используйте адрес проекта, созданный OpenServer.

## 6. Как работать с сайтом

### Покупателю

1. Нажмите «Создать аккаунт» в верхнем меню или откройте `/account.php?view=register`. Введите имя, email, необязательный телефон, пароль (от 10 символов) и его подтверждение. После регистрации откроется личный кабинет.
2. Для повторного входа откройте `/account.php?view=login`; пароль можно сменить в кабинете. Для выхода нажмите «Выйти».
3. На главной странице в блоке «Билеты на фестиваль» нажмите «Добавить в корзину».
4. В корзине измените количество кнопкой «Обновить» (от 1 до 5 за одну позицию) или удалите билет.
5. Нажмите «Перейти к оформлению».
6. Введите имя и фамилию, email и телефон. При входе в аккаунт данные заполняются автоматически. Нажмите «Подтвердить заказ».
7. Увидите номер заказа. Заказ появится у администратора и, если покупатель вошёл, в его личном кабинете. Остаток билетов уменьшится.
8. Если нужна анкета участника, вернитесь на главную страницу и заполните раздел «Регистрация на фестиваль». Анкета сохраняется отдельно от заказа.

Цена и остаток при оформлении считываются повторно из MySQL. Если билет успели раскупить, заказ не создаётся, а покупатель возвращается в корзину с сообщением.

### Администратору

1. Откройте /admin/index.php и войдите с созданными учётными данными.
2. «Билеты»: заполните форму добавления; у существующего билета нажмите «Изменить». Кнопки «Скрыть» и «Показать» управляют его отображением в каталоге.
3. «Заказы»: просмотрите состав заказа и контакты покупателя. Выберите «Подтверждён» или «Отменён» и сохраните статус. Отмена возвращает билеты на склад; отменённый заказ повторно активировать нельзя.
4. «Анкеты»: просмотрите данные, указанные участниками. Этот раздел не заменяет список заказов.
5. «Главная страница»: измените заголовок и краткое описание, затем обновите главную страницу сайта в другой вкладке.
6. Кнопка «Выйти» завершает вход в панель.

## 7. База данных и связи

- admins — пользователи панели и хеши паролей.
- users — аккаунты покупателей, email, контакты и хеши паролей.
- site_settings — редактируемые тексты главной страницы.
- products — билеты, цены, остатки, признак показа.
- orders — контактные данные покупателя, сумма, статус, дата и необязательная связь user_id с аккаунтом.
- order_items — позиции заказа со снимком названия и цены на момент покупки.
- registrations — анкеты участников.

Связь users → orders: один покупатель может иметь несколько заказов. Гостевой заказ не привязан к аккаунту и остаётся в базе. Связь orders → order_items: один заказ содержит одну или несколько позиций. Поле order_items.product_id связывает позицию с текущим билетом, а product_name и unit_price сохраняют историю заказа даже после изменения каталога.

## 8. Проверка после установки

Выполните сценарий от начала до конца:

1. Откройте регистрацию покупателя и создайте аккаунт; войдите, смените пароль и проверьте повторный вход.
2. Откройте главную страницу: должны быть видны три примера билетов.
3. Добавьте один билет в корзину и измените количество на 2.
4. Оформите заказ. Запишите номер заказа со страницы подтверждения.
5. Войдите в панель: найдите этот номер в «Заказах» и проверьте сумму и состав.
6. Отмените заказ: остаток билета в каталоге должен увеличиться на 2.
7. Измените цену или название билета в панели и обновите главную страницу.
8. Заполните анкету участника и найдите её в разделе «Анкеты».
9. Измените текст главной страницы в панели и проверьте результат на сайте.

Проверка синтаксиса всех PHP-файлов в консоли OpenServer:

    for /R %f in (*.php) do php -l "%f"

Эту команду вводят в CMD. Если она находится в .bat-файле, используйте %%f вместо %f.

### Фактически выполненная проверка

На установленных PHP 8.5.4 и MySQL 8.4.11 успешно проверены: импорт database/schema.sql, создание администратора, открытие каталога, добавление билета в корзину, изменение количества до 2, заказ на 5 000,00 ₽, сохранение анкеты, вход в панель, просмотр заказа и анкеты, отмена заказа, редактирование текста главной страницы и билета. После отмены остаток проверяемого билета вернулся к 100, а заказ получил статус cancelled. Запрос к панели без входа показал форму авторизации; POST без CSRF-токена вернул HTTP 403. Проверка выполнялась на отдельной тестовой базе, которую после теста удалили. Затем создана рабочая база ritm_goroda с тремя примерами билетов и отдельным пользователем arina_site. Рабочий сайт вернул HTTP 200 по адресу http://127.0.0.1:8000/. Затем на рабочей базе проверены регистрация покупателя, запрет повторного email, отказ при неверном пароле, вход, смена пароля, покупка после входа и отображение заказа в кабинете. Тестовый аккаунт и заказ удалены с возвратом остатка; прежний заказ сохранился. Проверка Windows/OpenServer остаётся за пользователем после переноса.

## 9. Если что-то не работает

- Вместо сайта видно текст PHP: файл открыт через file:///. Откройте домен проекта через OpenServer.
- Проект не найден: проверьте путь home\ritm-goroda.local, имя секции в .osp\project.ini, папку public и перезапуск OpenServer.
- «Нет подключения к MySQL»: проверьте, включён ли MySQL, совпадает ли db_host с именем модуля, а db_name и пароль — с созданной базой.
- «could not find driver»: в выбранном PHP включите pdo_mysql и перезапустите PHP-модуль.
- Не удаётся войти: заново проверьте имя пользователя и создайте нового администратора через bin\create_admin.php.
- «Неверный защитный токен»: обновите страницу и повторите отправку; проверьте работу сессий и cookies.
- Билет отсутствует в каталоге: проверьте в панели, что он показан и есть в наличии.

## 10. Технические решения и ограничения

Данные из форм проверяются на сервере. SQL-запросы с пользовательскими значениями подготовлены через PDO; вывод данных экранируется. Пароли администраторов и покупателей хранятся как адаптивные хеши: Argon2id (19 МиБ, 2 прохода; параллелизм PHP по умолчанию), а при отсутствии поддержки Argon2id — bcrypt с cost 12. Проверка выполняется через password_verify. После успешного входа устаревший хеш обновляется через password_needs_rehash без хранения исходного пароля. Подробная проверка описана в parols.docx. Для меняющих данные форм используется CSRF-токен. Создание заказа и изменение остатков выполняются в транзакции с блокировкой строк билетов.

Проект предназначен для учебной локальной работы. Здесь нет онлайн-оплаты, отправки писем, доставки электронных билетов, восстановления пароля по email и поиска по всем заказам. В списках панели показываются последние 100 заказов и анкет. Для публичного запуска понадобятся дополнительные настройки сервера, резервное копирование и интеграция с платёжной системой.
